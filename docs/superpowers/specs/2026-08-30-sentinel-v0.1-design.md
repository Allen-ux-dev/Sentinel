# Sentinel v0.1 Design

## Goal
Build a native macOS “哨兵模式 / Sentry Mode” utility that keeps the real macOS lock screen in charge of authentication while adding a calm, vector-drawn living eye overlay, local device-event monitoring, a local timeline, and a lightweight watchdog.

## Product principles
- Native Swift/SwiftUI/AppKit; no Electron or WebView.
- The login password and Touch ID remain entirely owned by macOS. Sentinel never reads password text, key presses, fingerprint data, or Secure Enclave data.
- The eye is abstract vector art: a complete circular outer ring, a floating eye-shaped pair of Bézier eyelids inside it, small left/right gaps between the eye corners and outer ring, circular iris/pupil, restrained highlight, and subtle radial texture.
- Motion should feel alive but calm: slow breathing, damped cursor tracking, natural blinking, reaction variants, and anti-repeat scheduling.
- All event history is local-only in v0.1.
- Lock-screen overlay uses SkyLightWindow when available, with a normal-window fallback and runtime failure isolation.
- Chinese and English are first-class UI languages. The setting supports System / 简体中文 / English.

## v0.1 feature scope
### Activation
- Manual “Start Sentry” with configurable 0/3/5/10 second countdown; default 5 seconds and “Enter Now”.
- Optional auto-arm when macOS locks; default on after the user enables it.
- Use the real macOS Lock Screen. Programmatic locking uses the standard Control-Command-Q action through CGEvent and therefore requires Accessibility permission; if unavailable, clearly instruct the user to lock manually.

### Lock screen overlay
- One overlay per active display, centered and non-interactive.
- Eye, title, and one short status line by default.
- Optional 2–3 most recent privacy-safe event summaries; default off.
- Hide immediately when the user session unlocks.

### Eye engine
States: idle, tracking, blink, focus, alertHigh, alertLow, sleeping, waking, success.
Priority: alert > authentication reaction > monitored event > blink > tracking > breathing.

Base behavior:
- breathing around 3–4 seconds with slight timing/scale variation;
- pupil/iris follows cursor with damping and bounded travel;
- occasional natural blink / small gaze drift;
- no realistic blood vessels, skin, or photographic eyeball assets.

Authentication failure reaction pool:
- pupil constrict, squint, glance left/right, single blink, double blink, inner-eye shrink, subtle ring ripple, short pupil offset, wake-and-focus.
- Exclude the three most recently used reactions.
- Approximately 5% chance of a restrained “easter egg” glance/pause, also anti-repeated.
- Password and Touch ID may use different visual weight if the OS can reliably identify the source. If not, present a generic authentication failure reaction.

### Authentication boundary
macOS has no stable public API for observing every lock-screen password/Touch ID failure. v0.1 therefore defines an AuthenticationOutcomeMonitor interface and includes an experimental system-log adapter that only looks for authentication outcome messages. It must never capture keyboard input. The app exposes adapter availability in diagnostics and provides a debug reaction simulator so the entire eye/reaction engine can be tested without pretending the OS signal is guaranteed.

Thresholds:
- configurable failure count; default 3;
- configurable rolling window; default 120 seconds;
- success resets the count immediately;
- threshold enters high alert for default 10 seconds, then low alert until successful unlock.

### Monitored events
- network path lost/restored;
- AC power connected/disconnected;
- USB device topology changed;
- session sleep/wake and lock/unlock;
- watchdog interruption/recovery status.
Ordinary events are silent and only produce a subtle eye response plus timeline entry.

### Alerting
Only two v0.1 conditions become true alerts:
1. authentication failures crossing the configured threshold;
2. Sentinel monitoring unexpectedly stopping / failing recovery.
Ordinary network/power/USB events do not sound alarms.
A true alert emits one restrained system sound at most once per alert entry; no looping siren.

### Timeline and retention
- Local JSON-backed event store under `~/Library/Application Support/Sentinel/`.
- Default retention 7 days, configurable.
- Lock-screen summaries omit usernames, IP addresses, USB serial numbers, and other identifying details.
- One-click clear history.

### Watchdog
- A lightweight helper receives main-app heartbeat through a timestamp file.
- Active/intentional-shutdown marker distinguishes a crash from normal disarming/quit.
- If armed heartbeat becomes stale, helper attempts app relaunch.
- Retry budget: default maximum 3 attempts in 5 minutes; then stop to avoid a crash loop.
- Helper status is written separately so the main app can import recovery/failure events without concurrent event-store writes.

### Restart/login behavior
- Helper may start at login.
- If “launch at login” is enabled, helper opens Sentinel after login.
- Normal shutdown/reboot is not an alert.
- Auto-arm preference persists; the next real lock event arms according to settings.

## Architecture
### SentinelCore
Platform-light logic with deterministic tests:
- event models and severities;
- settings model and defaults;
- rolling authentication failure tracker;
- reaction selector with anti-repeat behavior;
- eye-state reducer;
- retry budget;
- retention pruning;
- bilingual string catalog.

### Sentinel app
macOS-only target:
- `SentinelApp` / AppDelegate;
- Dashboard, Events, Settings, Diagnostics;
- SentryCoordinator/event bus;
- Eye renderer/model/controller;
- overlay window manager + SkyLightWindow bridge;
- lock-screen service and Accessibility permission state;
- network, power, USB, wake/sleep, lock/unlock, experimental authentication monitors;
- JSON stores and heartbeat writer.

### SentinelHelper
Foundation-only executable:
- reads settings/active marker/heartbeat;
- enforces retry budget;
- relaunches bundle by identifier;
- writes helper status.

## Failure isolation
- Overlay failure must never block macOS locking or unlocking.
- A monitor failure is recorded but does not stop other monitors.
- Event-store write errors do not block state updates.
- Unsupported SkyLight behavior falls back to a normal overlay/window or no overlay while monitoring continues.
- Experimental auth outcome detection reports “unavailable” rather than fabricating data.

## Packaging
- Swift Package layout for source/test simplicity.
- `Build.command` builds release binaries, assembles `Sentinel.app`, ad-hoc signs, verifies the staged bundle, safely installs/updates `/Applications/Sentinel.app`, and installs a user LaunchAgent for the helper.
- User data/settings remain in Application Support and survive app replacement.

## Validation
- Core behavior covered by Swift tests runnable without macOS UI frameworks.
- macOS-only manual validation checklist covers true locking, overlay visibility, Accessibility permission, multiple displays, sleep/wake, power, USB, network, helper relaunch, and authentication adapter availability.
